# Octobench Real-Commit Benchmark

Comparing coding agents on **25 real, recent, fail-to-pass-proven tasks** harvested
from merged pull requests in trusted open-source projects — 5 languages
(python, php, rust, cpp, js), scenario mix from one-line crash fixes to
multi-surface features, graded by the projects' own held-out tests plus an LLM
judge.

Providers under test (each runs its stock single-agent invocation):

| provider | invocation | model |
|---|---|---|
| claude | `claude -p --output-format stream-json --dangerously-skip-permissions` | claude-opus-5 |
| octomind | `octomind run developer:general --format=jsonl` | ollama:glm-5.2 |
| codex | `codex exec` | gpt-5.6-sol |

## What a case is

Each case in `cases/dev/` and `cases/dev2/` reconstructs a real merged PR as a
task (see `AGENTS.md` → "Real-Commit Case Harvesting" for the full pipeline and
rules):

- **`case.yaml`** — the task `instruction` (either a reverse-engineered spec via
  the `developer:reverse-spec` tap agent, or the original GitHub issue text for
  `prompt_source: original-issue` cases) plus `meta` (repo, base/gold SHAs, PR,
  held-out `test_paths`).
- **`setup.sh`** — shallow-fetches the pre-fix BASE commit (single reachable
  commit: the fix is not in the object store), prepares the toolchain
  (pip/composer/npm/cargo/cmake), removes the git remote.
- **`validate.sh`** — after the agent runs, fetches the gold commit and checks
  out ONLY the held-out test paths (agent edits to tests are overwritten), then
  runs those tests selectively. Non-zero exit = task failed.
- **`quality.sh`** — cheap objective build/lint sanity.

Every case is proven **fail-to-pass** before benching
(`scripts/verify_case.sh <case_dir>`): tests must fail at BASE and pass with the
real merged fix applied. Every held-out assertion was audited to be derivable
from the instruction (no grading on undisclosed prose/formatting picks).

## Scoring

Per case: hidden-test validation (hard pass/fail, failure costs a 25-point
penalty) + LLM judge score 0-100 (judge = octomind `judge` role, model from
`OCTOBENCH_JUDGE_MODEL`) weighted 0.85 with an efficiency component weighted
0.15. Costs: claude reports its own `total_cost_usd` (correct 1h-cache-write
pricing); other providers are priced from token counts × `configs/models.yaml`.

## Reproduce

On a linux host with docker (agents authenticate via env keys + mounted CLI
logins — see `runners/executor.py` `AUTH_ENV_KEYS`):

```bash
# 1. Agent image (toolchains for all 5 languages + pinned agent CLIs)
docker build -f docker/Dockerfile.agent -t octobench-agent:latest docker

# 2. Prove every case fail-to-pass (optional but recommended)
for c in cases/dev/*/* cases/dev2/*/*; do scripts/verify_case.sh "$c"; done

# 3. Run per provider (see run_full_*.sh for the exact wrappers used)
export OCTOBENCH_JUDGE_MODEL=ollama:minimax-m3
python -m cli.main run --cases cases/dev  --config configs/run-matrix.cases-claude.yaml \
  --executor docker --image octobench-agent:latest --out results-full-claude
python -m cli.main run --cases cases/dev2 --config configs/run-matrix.cases-claude.yaml \
  --executor docker --image octobench-agent:latest --out results-full-claude
# same with run-matrix.cases-octomind.yaml / run-matrix.cases-codex.yaml

# 4. Retry infra failures (provider 5xx etc.) and repair degenerate judge verdicts
python scripts/rerun_failed.py results-full-claude/<ts>/results.json configs/run-matrix.cases-claude.yaml
python scripts/rejudge.py     results-full-claude/<ts>/results.json

# 5. Aggregate table
python scripts/full_table.py 'results-full-claude/*/results.json' 'results-full-octomind/*/results.json'
```

Provider-specific env used in our runs: octomind ran a staged tap
(`OCTOMIND_TAP_CACHE`) and a binary override with the unfinished-handback
pre-gate (`OCTOMIND_BIN`); codex needed `CODEX_BIN` pointing at >= 0.145.0 for
gpt-5.6-sol. Ollama cloud (`OLLAMA_API_KEY`) has no prompt caching — factor
that into cost comparisons (anthropic caching re-reads context at 0.1× input
price).

## Case collection (adding more)

`scripts/reverse_spec.sh <repo_url> <gold_sha> [out.md]` reconstructs the task
from a merged commit via the `developer:reverse-spec` agent; curate its Task
Prompt (plus the spec requirements whenever hidden tests pin API names, wire
formats, or exact output) into `case.yaml`. For issue-driven cases use the
original issue text, trimmed of fix-leaking sections. Full criteria and the
derivability rule: `AGENTS.md` → "Real-Commit Case Harvesting".
